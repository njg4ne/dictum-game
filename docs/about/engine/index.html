The students' engine

Every word you guess starts in a piece of Python that students wrote. The engine reads the Wheelock's Latin vocabulary, finds every form each word can take, and builds the lists the game plays. Without it there would be no Latin to guess. It runs in your browser, not on a server.

  • 5teams
  • 11students
  • 720lines of Python
  • 84tests
  • 54submissions

The teams wrote about 720 lines of Python in all, and the course's automatic grader checked 54 submissions over five days.

The engine in src/lib/engine/engine.py combines the best ideas from the five teams' submissions to the course's data-engine assignment, rewritten from scratch around ideas the students had first. Each team solved the problem in a different shape, from one compact file to several small ones, and each shape taught something. Every team's final submission passed all of the automatic checks.

Techniques worth noticing #

Congratulations to every team whose ideas are in the engine. These were first-semester programmers, and each choice below is a real engineering choice.

  • Team Lux (Adriana Aviles-Reynado, Kyle Patterson) · Team Via (Boris Pekar, Ray Hutton)

    Cheap sorting first, slow lookup last. They picked the vocabulary rows by chapter and part of speech first, and only then ran the slow lookup. Asking for nouns never looks up a verb, and choosing nothing never touches the library. Measured, nouns from all 40 chapters took 0.19 s this way against 0.44 s the other way.

  • Team Via (Boris Pekar, Ray Hutton)

    Accepting input in more than one form. One function accepts a part of speech as the library's own type, as its code ("V") or as a plain word ("verb"). It tries the library's type first and falls back to a lookup table, and casefold() makes capital letters not matter.

  • Team Via (Boris Pekar, Ray Hutton)

    Asking the data instead of typing in lists. available_choices() reads the chapters and parts of speech out of the vocabulary file, so a menu built from it never offers something that is not there. The instructor page builds its checkboxes this way.

  • Team Lux (Adriana Aviles-Reynado, Kyle Patterson)

    A recipe of small, named steps. The main function reads like a plan: get the vocabulary, filter by chapter, filter by part of speech, get the forms. Each step is its own small function with a note on what goes in and what comes out.

  • Team Lux (Adriana Aviles-Reynado, Kyle Patterson)

    One rule in one line. The built-in all() checks that every condition holds. The students' test for each chosen grammar tag is tag_part not in row or row[tag_part] in values. In plain words: keep the form if it does not have that tag, or if its value is one of the chosen ones. That one test is the whole tag filter.

  • Team Silva (Carden Zhang, Diego Gutierrez) · Team Mons (Candice Choi, Ismoil Salimov, Hallie Nguyen)

    Spotting a rule nobody wrote down. Each noticed that nouns have no tense, so choosing a tense must not throw nouns away. Teams Lux and Via handled it too, in a general way.Why this matters

  • Team Pons (Senitha Senaratne, Fahad Waqar)

    One bad item must not stop the rest. Each lookup sits in a try/except block. If one word fails, the code skips it and carries on, so one failure does not lose the whole list.

  • Team Via (Boris Pekar, Ray Hutton)

    Small safety habits. Creating a missing folder before saving, and skipping vocabulary rows with an empty cell instead of crashing on them.

Why nouns keep their place when you pick a tense #

Tense belongs to verbs. It says when something happens: amat (present), amabat (imperfect), amabit (future). A noun such as puella has a case and a number, but no tense at all.

So what should happen when an instructor ticks “present” under tense? A filter that only asks “is the tense present?” would throw away every noun, because a noun has no tense to check, and the instructor would lose words they never meant to leave out. Teams Silva and Mons noticed this, and Teams Lux and Via solved it in a general way: a form passes the filter if it has no such property, or if its value is one of the ones chosen.

That is why choosing “present” keeps all of your nouns and only the present-tense verbs. The instructor tools say the same thing next to the choices.

Why these approaches were chosen #

Each team wrote one function, build_word_file, on top of the same Latin library. All five were run unchanged on the same vocabulary, and the engine takes the best of each. Every team's final submission passed all of the automatic checks. The full notes are in src/lib/engine/PROFILING.md.

  • Bundled vocabulary (Teams Lux, Via and Mons): shipping the vocabulary with the code means building a list makes no network requests and works offline. The engine does the same.
  • Cheap sorting first (Teams Lux and Via): choosing the matching vocabulary rows before the slow lookup was about twice as fast as looking up everything and filtering afterwards.
  • Part of speech (Teams Lux, Via and Mons): telling the library each word's part of speech picks the right word when several share a spelling.
  • Careful edge cases (every team): missing folders, blank cells, nouns having no tense and a failed lookup were each handled by at least one team. The engine adds one more: names such as Asiae are lowercased, because the game can only type lowercase a-z.
